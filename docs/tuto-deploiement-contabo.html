2

Configurer votre Nom de Domaine avec Cloudflare (SSL Gratuit)

Activation du HTTPS, des WebSockets sécurisés (WSS) et du proxy anti-DDoS sans manipulation complexe de certificats.

Pour que les navigateurs mobiles autorisent le jeu en ligne, les paiements et le PWA, le protocole HTTPS et les WebSockets WSS sont obligatoires. La méthode la plus performante et sécurisée consiste à utiliser Cloudflare en frontal.

  1. Achetez votre nom de domaine chez le registrar de votre choix (ex: Namecheap, Hostinger, GoDaddy, OVH...).
  2. Créez un compte gratuit sur Cloudflare.com et ajoutez votre domaine.
  3. Chez votre registrar, modifiez les serveurs DNS (Nameservers) pour pointer vers ceux fournis par Cloudflare.
  4. Dans l'interface Cloudflare, ouvrez l'onglet DNS > Records et ajoutez les enregistrements suivants :
Type Nom (Name) Contenu (IPv4 Address) Proxy Status TTL
A @ (racine) VOTRE_IP_CONTABO (ex: 161.97.142.88) 🟠 Proxied Auto
A www VOTRE_IP_CONTABO (ex: 161.97.142.88) 🟠 Proxied Auto
⚡
Réglages Cloudflare Critiques :
  • SSL/TLS > Overview : Sélectionnez le mode « Flexible » (ou « Full » si vous activez un certificat origin).
  • SSL/TLS > Edge Certificates : Activez « Always Use HTTPS ».
  • Network : Vérifiez que l'option « WebSockets » est bien cochée sur ON.

Connexion SSH & Récupération du Code

Connexion à votre serveur Ubuntu et clonage du projet.

Ouvrez votre terminal (PowerShell sur Windows, Terminal sur macOS ou Linux) et connectez-vous à votre VPS :

bash 
ssh root@<IP_DE_VOTRE_VPS_CONTABO>

Mettez à jour les paquets système et installez Git :

bash 
apt-get update && apt-get upgrade -y
apt-get install -y git curl

Clonez le code de votre casino dans le répertoire de production :

bash 
git clone https://github.com/<votre-utilisateur-ou-organisation>/casino-mdg.git /var/www/casino-mdg
cd /var/www/casino-mdg
4

Lancer le Déploiement Automatisé en 1 Seule Commande

Configuration du Swap 4 Go, limites noyau sysctl, Docker, génération des clés de sécurité et compilation des conteneurs.

Nous avons créé pour vous le script d'automatisation complet scripts/deploy/deploy-contabo.sh. Il réalise toutes les tâches d'infrastructure en une seule exécution :

bash 
bash scripts/deploy/deploy-contabo.sh
🛡️
Ce que le script configure automatiquement pour vous :
  1. Swapfile de 4 Go : Protège la machine contre les plantages mémoire (OOM) lors des pics de connexions.
  2. Optimisations Noyau Linux : Active vm.overcommit_memory = 1 pour Redis et augmente les descripteurs de fichiers à 65536.
  3. Pare-feu UFW : Ouvre exclusivement les ports 22 (SSH), 80 (HTTP/WS) et 443 (HTTPS).
  4. Génération de Clés Cryptographiques : Génère des clés aléatoires sécurisées de 64 caractères dans .env.production.
  5. Lancement Docker : Construit et démarre PostgreSQL, PgBouncer, Redis, RabbitMQ, MinIO, Celery, le moteur Go et Nginx.

Après 2 à 3 minutes de compilation, le script affiche le récapitulatif avec votre adresse IP publique prête à l'emploi.

5

Renseigner votre Nom de Domaine dans la Configuration

Déclaration de votre domaine pour autoriser les requêtes CORS et l'en-tête Host de Django.

Ouvrez le fichier de configuration de production généré :

bash 
nano .env.production

Modifiez les lignes ALLOWED_HOSTS et CORS_ALLOWED_ORIGINS avec votre nom de domaine réel :

env 
ALLOWED_HOSTS=votre-casino.com,www.votre-casino.com,127.0.0.1,backend
CORS_ALLOWED_ORIGINS=https://votre-casino.com,https://www.votre-casino.com

Sauvegardez avec Ctrl + O puis validez par Entrée, et quittez avec Ctrl + X.

Rechargez les conteneurs avec la nouvelle configuration en quelques secondes :

bash 
docker compose -f docker-compose.prod.yml --env-file .env.production up -d

bash

bash
git pull origin master
docker compose -f docker-compose.prod.yml --env-file .env.production up -d --build

Dépannage & Questions Fréquentes (FAQ)

Q : Mon domaine affiche une page d'attente ou « 502 Bad Gateway » lors des premières minutes ?

R : Les conteneurs peuvent prendre entre 45 et 90 secondes pour finaliser les migrations initiales et les vérifications de santé. Vérifiez l'avancement avec docker compose -f docker-compose.prod.yml logs backend. Assurez-vous également que le mode SSL dans Cloudflare est bien configuré sur Flexible.

Q : Les WebSockets ne se connectent pas (erreur de connexion à la table de jeu) ?

R : Vérifiez que dans votre tableau de bord Cloudflare > onglet Network, la case WebSockets est bien cochée sur ON. Cloudflare gère automatiquement la mise à niveau du protocole vers wss://.

Q : Comment redémarrer l'ensemble des services en cas de besoin ?

R : Exécutez simplement docker compose -f docker-compose.prod.yml restart. Pour un arrêt et redémarrage complet : docker compose -f docker-compose.prod.yml down && docker compose -f docker-compose.prod.yml up -d.
